# Backend Database Reference

The workspace-level `Documents/DATABASE.md` is the canonical schema. Keep Prisma models aligned with it.

## Current state
- Prisma CLI and `@prisma/client`: **7.10.1**
- Schema: `prisma/schema.prisma`
- Config: `prisma.config.ts` (reads `DATABASE_URL`)
- Client output: `src/generated/prisma` (gitignored)
- Migrations: `prisma/migrations/`

## MVP entities in schema
`user_profiles`, `societies`, `buildings`, `units`, `society_memberships`, `notices`, `visitors`, `audit_logs`

## Commands

```bash
npm run prisma:validate
npm run prisma:generate
npm run prisma:migrate
```

`prisma:migrate` requires a development `DATABASE_URL` and creates/applies migrations under `prisma/migrations/`. Do not use `db push` for the initial workflow. Do not point migrate at production. Do not reset shared databases.

## Workflow
1. Confirm the change against `Documents/DATABASE.md`.
2. Edit `prisma/schema.prisma`.
3. Run `npm run prisma:validate`.
4. Run `npm run prisma:migrate` against a development database (creates a reviewed migration).
5. Run `npm run prisma:generate` if the client was not regenerated by migrate.
6. Add or update authorization/isolation tests with the feature that uses the model.

## Prerequisites
- Local Prisma CLI must be installed under this repository's `node_modules` (see `docs/SETUP.md` if `@prisma` is root-owned).
- A development PostgreSQL database and `DATABASE_URL` are required before migrate.
- Maintenance and service-directory tables are intentionally absent until approved.
